# 2026-06-26 — Vantage Auth Bugfixes

## Context
User-reported two auth bugs after previous fixes:
1. Google OAuth: "Could not verify your account" on sign-up
2. Email login: stuck on splash screen

## Root Causes Found
1. Two incompatible Supabase clients:
   - Login page: `createClient()` from `lib/supabase.ts` → sessionStorage, key `vantage-auth-token`
   - App state: `getSupabaseBrowserClient()` from `lib/auth/supabase-client.ts` → localStorage (default key)
   - Different storage means sessions invisible across pages
2. OAuth profile data lost when Google opens consent in new tab/window
3. `onAuthStateChange` firing on non-meaningful events
4. `mounted = true` in cleanup (should be `false`)
5. No error handling in `useAppState` — stuck on 'loading' forever

## Changes
1. **`lib/auth/supabase-client.ts`** — Updated `getSupabaseBrowserClient()` to use sessionStorage with key `vantage-auth-token` (same as `createClient()`). Added `detectSessionInUrl: true` for OAuth. Now both clients use identical storage.

2. **`lib/app-state.ts`** — Rewrote `useAppState`:
   - `resolveState()` function handles both initial session + auth changes
   - Filters `onAuthStateChange` to meaningful events only (SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED, USER_UPDATED)
   - Fixed `mounted = false` in cleanup
   - Full try/catch on profile fetch + getSession — never stays stuck
   - Cast `user_profiles` query `as any` (TS never-type issue with generic)

3. **`app/auth/complete/page.tsx`** — Complete rewrite:
   - 3-source profile resolution: sessionStorage → URL params → user metadata
   - VantageOrb 80px animated + "Setting up your account…" loading
   - Error state with "Back to Vantage" pill button
   - Suspense boundary for `useSearchParams()` (Next.js 15 requirement)
   - Login-page matching gradient background

4. **`lib/auth/oauth.ts`** — Passes profile via redirectTo URL params as backup for new-tab OAuth. Adds `access_type: 'offline', prompt: 'consent'`.

5. **`types/supabase.ts`** — Added `user_profiles` table to Database type

## Known Workaround
- `(.from('user_profiles') as any)` needed because TypeScript resolves `.from()` to `never` type — same as existing code in `app/actions/auth.ts`

## Bug 3 — Login routes to onboarding (June 26)
**Root cause**: `getSupabaseBrowserClient()` used `createBrowserClient` from `@supabase/ssr`, which OVERRIDES `auth.storage` with cookie-based storage (`createStorageFromOptions()`). Login page stored sessions in sessionStorage; main app looked in cookies → invisible → 'onboarding' state.

**Fix**: Switched to `createClient()` from `@supabase/supabase-js` directly (same library as login page). Both now use identical sessionStorage adapter.

**Also added**:
- Diagnostic console.logs throughout resolveState
- 'needs-quiz' AppState: profile exists but no investor_style → quiz directly
- Fix A: Metadata-based profile creation fallback (PGRST116 → reconstruct from auth metadata)
- OnboardingFlow `initialScreen` prop support
